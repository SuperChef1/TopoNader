# TopoNader 运行过程证据审计（2026-10-21）

## 判断

现有证据说明 TopoNader 的代理、架构生成、候选训练、FE 反馈与回滚机制实际运行，且在部分已观察案例中提高了同 FE 预算下的最佳值。但尚不足以证明 LLM 架构自适应稳定优于固定架构，更不能把整体优化增益全部归因于 LLM。当前最需要解决的是架构接受规则与实际寻优收益之间的错位，以及全局候选覆盖率修复造成的排序失真。

本次只读取过程文件，不启动训练、FE 或 LLM，不修改实验配置、状态和结果。项目已迁入 `web_plate/`；历史 manifest 中绝对路径仍指向迁移前位置，分析按当前目录和轮次定位文件。

## 数据与比较方法

- 每组对照截取双方都已完成的最大共同轮次，每轮请求数均为 20，比较相同实际 FE 尝试预算，而不是当前不同的终止轮次。
- 读取 config.snapshot.json、iterations.jsonl、manifest.json、fe_request.mat、fe_result.mat、feedback.json、audit/trace.json、agents/*.json、*.metrics.json 和累计 MAT。
- 三组对照内部初始数据 SHA-256 一致；配置只在实验名、architecture_adaptation、agents.enabled 上不同；不同载荷案例之间不直接比较目标值。
- 逐批核对每轮有效 FE 输入/输出是否原样进入共同终点的累计 MAT，并检查 manifest.sample_count 连续性。六条数据链均无错误。
- 此检查不等于独立重求解 FE，也不能确认历史每一轮使用的 .mph 载荷恒定；历史文件未逐轮提供模型二进制哈希。

## 有积极信号，但归因受到限制

6 杆第 12 轮：同批 FE 的 child pairwise accuracy 为 0.7316，parent 为 0.6053，且 child top-k regret 改善约 0.3295。采用新架构后至下一次审查前，best-so-far 较切换前增加约 0.05307。

6 杆第 34 轮：child pairwise accuracy 为 0.8105，parent 为 0.7474；到第 39 轮，best-so-far 较切换前增加约 0.02784。

这是目前较直接的“新架构有局部帮助”的证据，但同批 FE 结构由临时胜出模型驱动搜索，并不是父、子各自独立提出候选后的配对寻优试验。因此不能据此证明父架构继续运行一定更差。

原始载荷 4 杆的平均 batch pairwise accuracy：Baseline 0.5440，TopoNader 0.6122；但平均 top-k regret 分别为 0.14617、0.14722，TopoNader 没有同步改善 top-k，最终 FE 最佳值更低。两组评价发生在各自不同 FE 候选分布上，不能把平均排序指标直接解释为模型质量的公平离线对比。

## 明确的机制风险

### 1. 架构接受只要求相对更好，没有绝对质量及改善幅度门槛

原始载荷第 29 轮：child pairwise accuracy=0.3632，parent=0.3263；两者 Kendall tau 均为负、top-k recall 均为 0，child 仍被继承。

另一载荷 4 杆采用新架构的第 47、174、249、269、360 轮，child pairwise accuracy 也低于 0.5。0.5 仅是无并列独立随机排序的参照，不是这些相关 FE 样本上的显著性检验，但这些数值不支持强排序能力。

当前 selection.py 按 pairwise accuracy、Kendall tau、负 top-k regret、负 RMSE 依次排序。极小的 pairwise 优势可以压过 top-k 退化。例如原始载荷第 122 轮 child pairwise 提高 0.0895，但 top-k regret 恶化 0.1154，仍被继承。

每轮只有 20 个 FE 样本，虽然产生 190 个样本对，这些样本对并不独立，不能按 190 次独立试验估计置信度。反复在小 batch 上挑选架构会增加选择噪声。

### 2. 回滚架构不能回滚搜索轨迹

临时子架构先驱动候选搜索，再根据这批结构的 FE 标签与父模型预测比较。子架构被回滚时，该批 FE 数据仍保留，且没有在相同预算下验证父模型本来会选择的结构。因此“能回滚”不等于“试错不损失搜索机会”。

### 3. 全局候选的修复前后排序几乎失去关联

下表的修复比例按候选数加权；相关系数和 top-10 overlap 是每个池指标的算术平均。仅涵盖 shortlist 候选池，不是每代全部 PSO 粒子。

| 案例 / 方法 | 全局覆盖率修复比例 | 修复前后 Spearman 均值 | top-10 overlap 均值 |
|---|---:|---:|---:|
| 原始载荷 / Baseline | 85.76% | 0.0092 | 3.18% |
| 原始载荷 / TopoNader | 78.23% | 0.0279 | 1.56% |
| 另一载荷 / Baseline | 96.43% | 0.0090 | 1.99% |
| 另一载荷 / TopoNader | 79.91% | 0.0262 | 11.82% |
| 6 杆 / Baseline | 74.03% | 0.0109 | 1.28% |
| 6 杆 / TopoNader | 68.15% | 0.0271 | 3.08% |

这说明整个框架存在搜索目标与最终可行几何不匹配的问题，不是 LLM 特有缺陷。修复后重预测避免标签对应错位，但没有使连续 PSO 原始搜索目标等价于最终几何上的目标。MC-dropout 批次上下文也可能影响全局分数变化，所以不能把所有排序失真全部归因于宽度修复。

局部池修复后重复比例在六条轨迹中约 61.7%–63.4%，说明很多候选落到相同整数几何，最终唯一产出率约 33.3%–36.3%。这些是工程效率和探索有效性瓶颈。

### 4. 不确定性未显示稳定的错误识别信号

逐轮 FE batch 上 uncertainty 与绝对误差的 Spearman 相关均值：原始载荷 TopoNader -0.0466、另一载荷 TopoNader -0.0357、6 杆 TopoNader +0.0903。现有指标没有证明 MC-dropout 不确定性稳定校准。该指标也不直接等于 UCB 寻优价值，需消融后才能判断是否应关闭。

## 优先级建议

1. 保留本次结果，先复算各案例最优结构，确认物理目标和载荷一致，避免以偶发 FE 数值现象证明方法效果。
2. 对架构继承增加稳健门槛：至少要求有意义的排序改善，并限制 top-k regret 明显恶化；用共同历史/保留 FE 集验证，不依赖单个 20 样本 batch。具体阈值应在独立 pilot 上固定，不应看正式结果后调到获胜。
3. 增加短窗口 parent/challenger shadow 比较或分配有限的对照 FE 预算，检验搜索收益；明确预算代价。
4. 优先减轻覆盖率投影造成的候选排序改变和重复，例如约束感知 shortlist 重排/轻量可行域参数化；并为不确定性采样做消融。
5. 多个预先确定的配对随机种子，分别报告同 FE 预算下的轨迹、最终最优值、失败数、训练和 LLM 成本；不要挑选有利种子。
6. 比较固定架构、LLM 自适应、与同样训练预算的非 LLM 架构搜索；否则不能将“搜索更多架构”的收益归因于 LLM 本身。

## 结论的边界

可以说：框架已形成完整可运行闭环，局部架构改进存在实际信号；在两组已观察配对运行的共同预算点领先，在一组落后。

不能说：已证明稳定优于固定架构、已证明优势来自 LLM、已证明统计显著或额外计算成本值得。各案例只有一条随机轨迹，6 杆只完成共同前 39 轮，载荷与训练过程还存在历史模型/代码版本追踪不足。
